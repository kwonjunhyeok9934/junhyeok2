# 우리집 (junhyeok2)

두 사람이 함께 쓰는 모바일 웹앱(PWA). 아래 탭은 홈 · 가계부 · 일정 · 여행 네 칸이고,
가계부 칸 안에 가계부·식비·고정비·사둔것, 일정 칸 안에 스케줄·할일이 작은 탭으로 들어 있다.
설계: `docs/superpowers/specs/2026-09-05-couple-ledger-design.md`

- 화면: HTML/CSS/JS, 빌드 없음
- 데이터·로그인·실시간: Supabase (무료)
- 호스팅: Vercel (무료)

## 처음 설정 (한 번만)

1. **Supabase 프로젝트 생성** — https://supabase.com → New project (Region: Northeast Asia / Seoul)
2. **표 만들기** — 대시보드 SQL Editor에 `supabase/schema.sql` 전체를 붙여 실행 (여러 번 실행해도 안전하다)
3. **자가 가입 끄기** — Authentication → Sign In / Up → *Allow new users to sign up* **OFF**
   (끄지 않으면 누구나 계정을 만들어 들어올 수 있다)
4. **두 계정 만들기** — Authentication → Users → *Add user* → 이메일·비밀번호, *Auto Confirm User* 체크.
   표시 이름은 앱 설정 화면에서 바꿀 수 있다.
5. **연결 정보** — Project Settings → API의 *Project URL* 과 *Publishable key*(`sb_publishable_…`, 예전 이름 anon key)를 `js/config.js`에 넣는다
6. **Vercel 배포** — https://vercel.com → Add New Project → GitHub `junhyeok2` import → Framework *Other*, Build/Output 비움 → Deploy.
   이후 `main`에 푸시할 때마다 자동 배포된다.
7. **폰에 설치** — 배포 URL을 크롬으로 열고 ⋮ 메뉴 → *홈 화면에 추가*

## 동작 메모

가계부 조회 기간(1·3·6·12개월·직접 지정)은 폰에 기억된다. 뒤로가기는 열린 시트·설정을 먼저 닫고, 없으면 두 번 눌러 종료한다.

**통계 탭**(가계부 옆)은 지출을 **주 · 월 · 년** 으로 골라 카테고리별 원형 그래프로 보여 준다. 맨 위에 그 기간 합계와
지난 기간보다 얼마 더/덜 썼는지, 하루 평균이 나온다. 조각은 큰 것부터 다섯 개 + **기타** 까지만 그리고(더 많으면 색이
구별이 안 된다), 아래 목록에 이름·건수·퍼센트·금액을 다 적는다. 같은 카테고리는 기간을 옮겨도 같은 색이다.
조각을 누르면 가운데에 그 카테고리가 뜨고, 한 번 더 누르거나 목록 줄을 누르면 **자세히** 시트가 열린다 —
식비는 **어떻게**(배달·컬리·마트… 식비 탭 세트와 사 둔 것에서 읽는다, 가계부에 바로 적은 것은 '직접 적음'),
다른 카테고리는 **메모별**로 한 번 더 나누고, **누가 썼나**와 내역이 같이 나온다.

설정은 위의 작은 탭(**내 이름 · 기념일 · 알림 · 화면 · 카테고리**)으로 한 칸씩만 본다. 카테고리 칸 안에서도
**지출 · 수입 · 고정비 · 어디서 · 어떻게 · 여행 · 규칙** 칩을 골라 그 종류만 보고 추가한다.
카테고리는 이름이나 ✎ 를 누르면 그 자리에서 고치고, 기념일은 줄을 누르면 아래 칸이 그 기념일로 채워져 **저장**으로 고친다.

아래 탭바는 네 칸이고 그 안의 화면은 열 개다. 주소의 `#ledger` `#meal` `#fixed` `#pantry` `#schedule` `#todo` `#travel` `#trips` `#packing` 중 예전 것은 그대로라
알림에서 열리는 주소도 손대지 않았다. 탭바를 다시 누르면 그 칸에서 마지막으로 보던 화면으로 돌아온다.

여행 탭은 지도와 내 여행 두 화면이다.
지도는 전국 229개 시·군·구. 지역을 누르면 시트가 열려서 **다녀온 곳으로 칠하거나, 그 지역 여행 기록을 보거나, 여행 계획을 만든다.**
두 손가락으로 확대·이동할 수 있다(서울 자치구처럼 작은 곳은 확대해야 누르기 쉽다).
색은 두 가지다 — 여행 기록이 있는 지역은 진하게, 직접 칠한 곳은 연하게.
지역 이름은 글자가 들어갈 만큼 커 보일 때 나오고, 칠한 곳은 더 일찍 나온다. 겹치면 덜 중요한 쪽이 숨는다.
오른쪽 아래 ＋ 로 지도에서도 바로 여행을 만들 수 있고, 여행 상세에는 그 지역만 잘라 보여 주는 작은 지도가 있다.
지도 데이터를 다시 만드는 방법은 `docs/지도_데이터.md`.

여행 하나는 **어디(지역 여러 개) + 언제(기간)** 다. 이름은 안 적어도 된다 — 지역으로 짓는다.
제주시를 두 번 갔으면 다음 여행은 **제주시 3** 이 된다. 여행을 만들면 그 지역이 지도에 자동으로 칠해진다.

여행을 누르면 트리플처럼 위에서 아래로 **며칠째 → 준비물 → 일정** 이다.
- **준비물** 은 여행마다 새로 적지 않는다. 여행 칸의 *준비물* 화면에 늘 챙기는 것을 한 벌 적어 두면
  여행마다 그 목록이 그대로 나오고, 거기서 챙긴 것만 체크한다.
  **대분류**(의류·세면도구·전자기기·서류·기타, 직접 만들 수도 있다)로 묶이고, 항목을 누르면 이름·분류를 고친다.
  **떠나고 나면 접힌다** — 출발 전에는 펼쳐져 있고, 여행이 시작되면 `준비물 3/5` 한 줄로 접혀 일정이 위로 올라온다. 머리를 누르면 다시 펴진다.
- **여행 준비** 칸이 1일째 위에 있다. 항공권·숙소처럼 **떠나기 전에 결제한 것**을 여기에 적는다.
  날짜는 *결제한 날*이라 여행 기간 밖이어도 되고, 가계부에도 그 날짜로 들어간다.
- **일정** 은 2박 3일이면 세 칸이다. 칸마다 *어디를 갔는지* 줄을 계속 더한다.
  한 장소에 **지출을 여러 개** 달 수 있다 — 성산일출봉에서 티켓 5,000 + 굿즈 12,000 처럼
  (분류 + 금액) 줄을 원하는 만큼 붙인다. 분류는 식비·숙소비·티켓·주유비·비행기… 에서 고르거나 새로 만든다.
  금액을 적으면 **가계부에 '여행' 지출로 함께 들어간다** (식비와 같은 방식 — 지출 줄 하나 = 거래 하나,
  줄을 지우면 그 거래도 사라진다). 메모에 `경주시 · 티켓 · 첨성대` 처럼 남아서 가계부만 봐도 뭘 썼는지 안다.

**여행 탭을 처음 쓸 때 한 번**: Supabase SQL Editor 에 `supabase/schema.sql` **전체**를 실행한다
(27·29·31·33·35·37번이 여행 몫). 잘라서 붙이지 말고 파일을 통째로 붙여 **Run** 한 번이면 된다 —
여러 번 실행해도 안전하게 써 놨다. 덜 실행됐으면 여행·준비물 화면이 "schema.sql 전체를 한 번 실행해 주세요" 라고 알려 준다.
잘 깔렸는지 보고 싶으면 `supabase/check.sql` 을 붙여 실행한다 — 표·열·함수가 '있음' 인지 한눈에 나온다.

식비 탭은 한 주(월~일)의 아침·점심·저녁·야식을 적는다. 한 끼는 날짜·끼니·메뉴·누가·어디서를
하나씩 갖고, 그 아래 **'어떻게' 세트**(마트·컬리·배달…)를 여러 개 달 수 있다. 세트마다 산 품목과
가격을 줄 단위로 적고, **세트 하나가 가계부 거래 한 건**이 된다(영수증 한 장 = 거래 한 건).
세트를 하나도 안 달면 돈을 안 쓴 끼니다.
배달·포장·외식은 갈 때마다 가게가 달라서 **가게 이름** 칸이 따로 나오고, 배달에는 **배달료** 칸이
품목 맨 밑에 기본으로 놓인다(컬리·쿠팡·마트·편의점은 카테고리 이름이 곧 가게라 안 나온다).

'산 곳 추가' 에는 고른 **어디서** 에 넣어 둔 '어떻게' 만 나온다 (집: 컬리·윙잇·네이버·배달·포장·마트·편의점,
회사: 회사, 외식: 외식·포장). 나누는 곳은 설정 → 카테고리 → **어떻게** — 어디서마다 칸이 나뉘어 있고,
✎ 로 고치면 어느 어디서에 나올지 켜고 끌 수 있다. 한 칸에서 ✕ 를 누르면 다른 곳에도 나오는 것은
그 칸에서만 빠진다. **schema.sql 을 다시 한 번 실행해야** 반영된다 (처음 한 번 위처럼 나눠 준다).

**사둔것 탭**(고정비 옆)은 윙잇·컬리·쿠팡·마트·편의점에서 산 품목을 미리 담아 두는 곳이다.
오른쪽 아래 ＋ 로 담는데, 카테고리를 고르고 품목·가격을 줄줄이 적으면 된다.
**담는 순간 가계부에 지출 한 건으로 들어간다** — 장 볼 때 이미 카드에서 나간 돈이니까.
한 번 담은 것(한 번의 장보기)이 거래 한 건이고, 같이 담은 품목들의 합이 그 금액이다.

식비를 적을 때 세트의 드롭다운으로 그 품목을 꺼내고, 품목 줄 옆의 버튼으로 **몇 개 썼는지**
를 눌러 둔다. 같은 걸 여러 개 샀으면 담을 때 **개수**를 적는다(즉석밥 4개, 55,900원). 그러면
꺼내 오면 **한 개 먹은 것으로 시작**한다 — 끼니에 가져왔다는 것은 먹었다는 뜻이니까.
그래서 꺼내는 순간 **13,975원**이 잡히고, 사 둔 것은 3개로 준다. 더 먹었으면 버튼을 눌러
**1개 씀 → 2개 씀 → 3개 씀 → 다 씀 → 안 씀** 으로 돌린다.
꺼내 놓기만 하고 안 먹었으면 **안 씀** 으로 두면 된다. 남은 것만 다음 끼니의 드롭다운에 나온다.

한 개짜리는 **다 씀 → 남김 → 안 씀** 으로 돈다. **남김** 은 과자 한 봉지를 뜯어 조금 남긴 것처럼
**먹긴 했는데 남았다**는 뜻이다. 먹었으니 **값은 그 끼니에 들어가고**, 남았으니 사 둔 것에서
안 사라지고 다음 끼니의 드롭다운에 또 나온다(목록에는 '먹다 남김' 이라고 붙는다).
남은 걸 마저 먹는 끼니에서 **다 씀** 으로 두면 0원이다 — 값은 처음 뜯은 끼니가 이미 냈다
(과자 1,500원: 남김 1,500원 → 다 씀 0원, 합 1,500원). **schema.sql 을 다시 한 번 실행해야** 반영된다.

이 값은 **가계부로 다시 가지 않는다.** 돈은 장 본 날 이미 나갔다. 대신 **식비 합계**에는
들어간다 — 그 끼니에 얼마어치를 먹었는지가 식비 탭이 보여 주려는 것이기 때문이다.
그래서 **식비 합계(언제 얼마어치 먹었나)와 가계부 합계(언제 얼마를 썼나)는 서로 다르다.**
나누어떨어지지 않으면 **마지막 한 개가 잔돈을 가져간다**(3개에 10,000원이면 3,333 / 3,333 / 3,334)
— 다 쓰고 나면 합이 산 값과 정확히 같아진다.
담기 시트의 **📷 사진 찍기 / 🖼 스크린샷에서** 로 컬리·쿠팡·윙잇 주문 내역을 찍거나 고르면 품목·가격을 읽어
줄로 채워 준다. 글자가 조금 틀리게 읽히기도 해서 **바로 저장하지 않고** 고칠 수 있게 보여 주기만 한다.
사진은 폰 밖으로 안 나간다(브라우저 안에서 처리). 처음 한 번만 인식 데이터 5MB쯤을 받는다.
컬리·쿠팡·윙잇 주문 내역처럼 **글자가 또렷한 화면**일수록 잘 읽는다.
**스크린샷은 자르지 말고 통째로** 주는 게 낫다 — 잘라 주면 오히려 덜 읽는다(8개 → 5개).
글자 크기·칸 위치를 화면 전체에서 가늠하기 때문이다.

**규칙 탭**은 둘이 정해 둔 집안 규칙을 적어 두는 곳이다. 대분류(집안일·돈·생활…) 아래에
한 줄씩 넣고, 규칙 줄을 누르면 내용·분류를 고친다. 오른쪽 **＋1** 은 그 자리에서
**안 지킨 횟수**를 센다 — 자주 하는 일이라 시트를 열지 않고 한 번에 누르게 떼어 두었다.
잘못 눌렀으면 규칙을 눌러 시트에서 **−** 나 **0으로** 로 되돌린다. 분류 머리에는 그
분류의 횟수 합이 보인다. 돈과는 아무 상관이 없다 — 가계부를 건드리지 않는다.

**사둔것 탭을 처음 쓸 때 한 번**: `supabase/schema.sql` 전체를 한 번 실행해 표를 만든다.

품목 가격이 원본이고 가계부 거래 금액은 그 합계의 거울이라, 저장할 때마다 합계를 다시 계산해
거래에 쓴다. 저장은 `save_meal` RPC 한 번으로 원자적으로 처리하고(중간에 실패하면 아무것도
안 쓰인다), 끼니를 지우면 `meal_buys` 삭제 트리거가 연결된 거래까지 지워 고아 거래가 남지 않는다.

Supabase 무료 플랜은 일주일 동안 요청이 없으면 프로젝트를 **자동으로 일시정지**한다. 그러면 앱이 로그인부터 막힌다.
`.github/workflows/supabase-keepalive.yml` 이 매일 한 번(12:17 KST) 가벼운 조회를 보내 이를 막는다.
접속 정보는 `js/config.js` 에서 읽으므로 따로 설정할 것은 없고, Actions 탭에서 *Run workflow* 로 바로 돌려볼 수 있다.
프로젝트가 이미 멈췄다면 https://supabase.com/dashboard 에서 **Restore** 를 누르면 데이터 그대로 되살아난다.
GitHub 는 저장소에 60일 동안 활동이 없으면 예약 워크플로를 끄므로, 그때는 메일이 오고 Actions 탭에서 다시 켜면 된다.
