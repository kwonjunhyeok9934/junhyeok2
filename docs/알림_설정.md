# 알림(웹 푸시) 설정 순서

앱 코드는 이미 들어가 있다. Supabase 쪽에 아래를 한 번만 해주면 된다.

## 1. 표 만들기 (SQL Editor → New query)

```sql
create table if not exists push_subscriptions (
  id         bigint generated always as identity primary key,
  user_id    uuid not null references auth.users(id) on delete cascade,
  endpoint   text not null unique,
  p256dh     text not null,
  auth       text not null,
  created_at timestamptz not null default now()
);
alter table push_subscriptions enable row level security;
drop policy if exists "auth all" on push_subscriptions;
create policy "auth all" on push_subscriptions for all to authenticated using (true) with check (true);
```

## 2. 발송 함수 올리기

Supabase → 왼쪽 **Edge Functions** → **Deploy a new function** (또는 Create function) → *Via Editor*
- 이름: `notify`
- 에디터에 `supabase/functions/notify/index.ts` 내용 전체 붙이기
- **Deploy**
- 배포 후 함수 상세 → **Details/Settings** 에서 **Verify JWT (Enforce JWT verification)** 를 **끈다**.
  (대신 우리 함수는 `x-webhook-secret` 헤더로 검사한다)

## 3. 비밀값 넣기

Edge Functions → **Secrets** (또는 Project Settings → Edge Functions → Secrets) 에 4개 추가:

| 이름 | 값 |
|---|---|
| `VAPID_PUBLIC_KEY` | `js/config.js` 의 VAPID_PUBLIC_KEY 와 같은 값 |
| `VAPID_PRIVATE_KEY` | 채팅으로 받은 비밀 키 (저장소에는 없음) |
| `VAPID_SUBJECT` | `mailto:내이메일@example.com` |
| `WEBHOOK_SECRET` | 채팅으로 받은 웹훅 시크릿 |

## 4. 웹훅 (SQL 한 번으로)

`supabase/schema.sql` 19장의 SQL을 `<함수주소>`(예: `https://xxxx.supabase.co/functions/v1/rapid-task`)와
`<WEBHOOK_SECRET>`만 바꿔 SQL Editor에서 실행한다. INSERT 3개 + 할일 담당자 변경(UPDATE) 트리거가 만들어진다.

대시보드 웹훅 화면(Integrations → Database Webhooks)으로도 되지만, 담당자 변경 알림에 필요한
`actor`(누가 바꿨는지)는 SQL 트리거에서만 넣을 수 있으므로 SQL 방식을 쓴다.

## 4-구. (참고) 대시보드에서 웹훅 3개 켜기

Supabase → **Database** → **Webhooks** → **Create a new hook**. 아래를 3번 반복 (표만 다르게):

- Name: `notify-transactions` / `notify-todos` / `notify-events`
- Table: `transactions` / `todos` / `events`
- Events: **Insert** 만 체크
- Type: **Supabase Edge Functions** → 함수 `notify`
- HTTP Headers: **Add header** → `x-webhook-secret` = 3번의 WEBHOOK_SECRET 값
- Create

## 5. (선택) 매일 아침 8시 요약

SQL Editor → New query. `<프로젝트ref>` 와 `<WEBHOOK_SECRET>` 을 바꿔서 실행:

```sql
create extension if not exists pg_cron;
create extension if not exists pg_net;

select cron.schedule(
  'daily-notify',
  '0 23 * * *',   -- 한국 시간 08:00 (UTC 23:00)
  $$
  select net.http_post(
    url := 'https://<프로젝트ref>.supabase.co/functions/v1/notify',
    headers := '{"Content-Type":"application/json","x-webhook-secret":"<WEBHOOK_SECRET>"}'::jsonb,
    body := '{"kind":"daily"}'::jsonb
  );
  $$
);
```

프로젝트 ref 는 Project URL 의 `https://xxxxx.supabase.co` 에서 `xxxxx` 부분.
일정도 마감 할일도 없는 날은 보내지 않는다.

## 알림 종류

| 언제 | 누구에게 | 내용 |
|---|---|---|
| 가계부 기록 | 기록한 사람 빼고 | "OO님이 가계부에 기록했어요 · 식비 12,000원" |
| 할일 추가 | 추가한 사람 빼고 | "OO님이 할일을 추가했어요 · 세탁소" |
| 할일 담당자 지정/변경 | 새 담당자에게만 | "OO님이 할일을 맡겼어요 · 세탁소 (마감 9/10)" |
| 일정 추가 | 추가한 사람 빼고 | "OO님이 일정을 추가했어요 · 9/12 19:30 저녁 약속" |
| 매일 08:00 (선택) | 모두 | "오늘의 우리집 · 일정 2개 · 마감 할일 1개" |

## 6. 폰에서 켜기

앱 → 설정 → **알림 켜기** → 권한 허용. 두 폰 모두. "테스트 알림 보내기"로 표시 확인.
그 다음 한 폰에서 지출 하나 저장 → 다른 폰에 알림이 오면 성공.

## 안 될 때

- 알림 켜기 눌러도 반응 없음 → 폰 설정 → 앱 → 크롬(또는 우리집) → 알림 허용 확인
- 저장했는데 안 옴 → Supabase → Edge Functions → notify → **Logs** 에서 에러 확인.
  `403` 이면 웹훅 헤더의 시크릿이 Secrets 값과 다른 것.
- 함수 로그에 `push failed 401/403` → VAPID 키 짝이 안 맞음. 공개 키는 config.js 와 완전히 같아야 함.
